# 焦点模式与 1.6.1 各模块

## 一、焦点模式的核心机制

一个窗口内，账号是各自的 `<webview>` 标签页，全部保持实时运行。

1.5.x 的写法是 `webview { display:none } / webview.active { display:flex }`。非活动标签页被 Chromium 判定为隐藏，`requestAnimationFrame` 被停、Flash 自己降频，所以切回去要追帧——这是多开切换卡顿的根因。

1.6 起，所有 webview 的布局尺寸恒定，位置和缩放都写进同一个 `transform: translate3d(x,y,0) scale(s)`。transform 是纯合成属性，子帧按自身布局尺寸光栅化，父合成器只把 Surface 乘一个矩阵，页面本身不知道自己被缩小或移动，因此不重排、不重新计算 Flash 舞台、不重建合成器、不掉帧。

缩略图不是截图镜像，就是那个 webview 本身。用 `capturePage` 做缩略图会让被抓的页面在系统看来是隐藏的，节流照样上来，而且多一次像素拷贝。

所有几何写入收敛在 `applySlot()` 一个函数里，并带脏检查（`tab._fmSlotSig`）——`layout()` 在每次 resize、切换、重绘都会跑，但绝大多数视图的几何没变，重复写同样的 inline style 一样会触发样式重算和合成层更新。

## 二、两套布局

⌘⇧D 或控制簇上的 ▦ 循环，纯几何变化，不重载、不丢游戏状态。

条带布局（strip，默认）。主画面 + 底部或右侧一条实时缩略图。固定槽位：每个账号有恒定位置，正在主画面的那个留一个虚线占位框，其余缩略图切换时一格不动——打游戏时靠位置认账号，位置一变等于每回合重新找一遍。档位阶梯 1/2 到 1/10，按账号数自动挑最大能放下的一档，条带最多吃掉容器 32% 的厚度。缩略图整组居中；账号名字号跟缩略图宽度走，夹在 12–24px。

分区布局（sector）。2 个号左右，3–4 个号四宫格（0=左上，1=右上，2=左下，3=右下），方位固定。分割比例 F=0.68。基准尺寸 Mw×Mh 取大格的尺寸——大格尺寸只与容器和 F 有关，与谁被聚焦无关，所以切换时没有任何页面被 resize；聚焦的那个缩放恒为 1、只做平移，竞技辅助与截图的 1:1 坐标假设不受影响。非聚焦视图取 `min(小格宽/Mw, 小格高/Mh)` 并贴自己那一侧的外缘，于是切换动画天然是「朝自己的方位缩小、从自己的方位长大」。左缘留 44px 竖条放控制簇，那条底下没有游戏画面。账号数 ≥5 自动按条带渲染，偏好不变。

画质：主槽尺寸取偶数整数（带小数会让 Flash 舞台落在半像素上，Retina 屏发虚）；档位吸附到「缩放后正好是整数个设备像素」，避免边缘跨半个物理像素被插值。

切换动画：`transform` 过渡 260ms，`cubic-bezier(.32,.72,0,1)`，只在切换那一下开（`body.fm-switching`），resize、拖动、滚动都不带动画。键盘焦点在布局完成后立刻交出，动画纯视觉。

音频默认不静音条带里的账号——轮到谁是靠游戏自己的音效听出来的，静音等于把唯一的回合提示掐掉。

明确不做：回合检测、回合提示、自动切换、任何像素采样。多开时各账号网络延迟不同，浏览器层面的回合提示会误导。

## 三、模块划分

新功能都放独立文件，共享文件只加带 `if (window.XZ*)` 守卫的钩子，或者是没有监听者时即空操作的 `document.dispatchEvent(new CustomEvent('xz:…'))`。把新模块文件删掉，行为回到 1.5.x。

| 文件 | 全局对象 | 作用 |
|---|---|---|
| `focus-mode.js` `.css` | `XZFocus` | 焦点模式的几何、切换、缩略图覆盖层、偏好 |
| `command-palette.js` `.css` | `XZPalette` | ⌘K 命令面板 |
| `status-bar.js` `.css` + `status-metrics.js` | `XZStatus` | 帧率、CPU、账号连接状态；主进程侧采样 |
| `session-restore.js` + `session-client.js` | `XZSession` | 崩溃恢复，存 `userData/session.json` |
| `page-cleanup.js` | `XZCleanup` | 按站点隐藏广告位与杂项，可居中游戏 |
| `integer-scale.js` | `XZScale` | 整数倍缩放 |
| `auto-login.js` | `XZAutoLogin` | 按档案自动登录、记住上次游戏地址 |
| `ui-tokens.css` | — | 统一浮层的圆角、描边、投影、层级 |
| `onboarding.js` `.css` | `XZOnboard` | 首启引导与各路由空状态 |

约定：新模块文件用 ES5 语法，CSS 只用 Chromium 87 支持的特性；任何地方都不用 `backdrop-filter`（在 `<webview>` 上方会静默失效，还会让 Retina 游戏画面发虚）；不对活着的游戏 webview 做节流、隐藏、暂停、re-parent、resize 或截图。

## 四、已知限制

- 标签页在窗口之间移动必然重新加载：webview 换宿主窗口要重建，这是 Chromium 的约束。所以「紧急换布局」的实用答案是窗口内的分区布局，不是散成多窗口。
- 离开浏览路由（设置、笔记等页面）时所有游戏仍会暂停，`.route` 是 `display:none`。
- 分区布局最多 4 个账号；条带布局 ≥9 个号要滚动，滚出视口的缩略图会被 Chromium 降频。
- 焦点模式内切账号不会按档案重新应用 Flash 变速倍率。
- 自动登录只能处理页面 DOM 里的登录表单。Flash 影片内部的选服、进房、点开始不可脚本化；跨站 iframe 里的登录框也填不了。
